## ✨ امکانات نسخه ۱ (مرحله ۱)

| بخش | قابلیت‌ها |
|---|---|
| **مدیریت سرور** | اتصال بی‌نهایت پنل 3x-ui، تست اتصال زنده، سینک خودکار اینباندها، وضعیت CPU/RAM/Xray، رمز پنل رمزنگاری‌شده (AES-256-GCM) |
| **کلاینت چندسرور** | یک کلاینت → چند سرور/اینباند با یک UUID، لینک ساب یکپارچه، حجم/زمان/محدودیت IP، تمدید، ریست ترافیک، فعال/غیرفعال، حذف |
| **سابسکریپشن هوشمند** | خروجی base64 برای همه کلاینت‌ها، هدرهای `subscription-userinfo` / `profile-title`، صفحه وب برندشده با QR و دکمه «افزودن به برنامه» (v2rayNG, Hiddify, Streisand, Shadowrocket, NekoBox) |
| **ادمین/نماینده** | سهمیه ترافیک، سقف کلاینت، تاریخ انقضا، دسترسی به سرور/اینباند مشخص، برندینگ مجزا برای هر ادمین |
| **امنیت** | ورود با رمز (scrypt) + تأیید دومرحله‌ای TOTP، سشن httpOnly، لاگ رخدادها (Audit) |
| **داشبورد** | آمار زنده کلاینت/سرور/ترافیک، نمودار مصرف ۱۴ روزه، سلامت سرورها |
| **UI** | دارک لوکس (گلس‌مورفیسم + نئون)، تم روشن، فارسی/انگلیسی، RTL کامل، فونت وزیرمتن، موبایل‌فرندلی |
| **Worker** | سینک زمان‌بندی‌شده سرورها، انقضای خودکار کلاینت‌ها، پاک‌سازی تاریخچه |

> مراحل بعدی: فروشگاه وب + مینی‌اپ تلگرام، درگاه پرداخت، کیف پول، دامنه اختصاصی هر ادمین، مانیتورینگ و Incident، بکاپ زمان‌بندی‌شده به تلگرام، بات تلگرام، Marzban/Hiddify.

## 🔔 امکانات مرحله ۲-الف (مانیتورینگ، بکاپ، تلگرام، API)

- **مانیتورینگ حرفه‌ای** — آپ‌تایم ۲۴ساعته/۷روزه، تأخیر پاسخ، CPU/RAM، وضعیت Xray برای هر سرور + ثبت خودکار **Incident** (قطعی، خطای احراز هویت، توقف Xray، CPU بالا) و اطلاع‌رسانی لحظه‌ای هنگام بروز و برطرف‌شدن مشکل.
- **بکاپ زمان‌بندی‌شده** — `pg_dump` فشرده از کل پنل، ساعت اجرا و تعداد نگه‌داری قابل تنظیم، اجرای دستی، دانلود از پنل و **ارسال خودکار فایل بکاپ به تلگرام**.
- **بات تلگرام ادمین** — اعلان رخدادها، نتیجه بکاپ، ورود ادمین‌ها، یادآوری انقضا (۳ و ۱ روز قبل) و هشدار مصرف ترافیک (۸۰٪ و ۹۵٪) + دستورات `/status` `/clients` `/client <name>` `/expiring` `/incidents` `/backup` `/id`. هر ادمین با ثبت آی‌دی تلگرام فقط اعلان کلاینت‌های خودش را می‌گیرد؛ کلاینت‌های دارای آی‌دی تلگرام هم پیام مستقیم دریافت می‌کنند.
- **REST API v1** با کلیدهای `srp_…` (دسترسی read / write، ابطال فوری، آخرین استفاده): `/api/v1/me` · `/api/v1/servers` · `/api/v1/clients` (+ `:id`, `:id/reset`).
- **Webhook** با امضای HMAC-SHA256 (`x-srp-signature`)، انتخاب رویداد، تست دستی و تلاش مجدد خودکار (۶ بار با backoff).

## 🛒 امکانات مرحله ۲-ب (فروشگاه، کیف پول، پرداخت)

| بخش | امکانات |
|---|---|
| **فروشگاه اختصاصی هر ادمین** | لینک `/shop/<slug>` (یا دامنه اختصاصی `https://shop.example.com/shop`)، برندینگ (لوگو/رنگ)، قوانین فروشگاه، لینک پشتیبانی، اجبار شناسه تلگرام/موبایل |
| **پلن‌ها** | حجم/مدت/کاربر، قیمت و قیمت قبلی (خط‌خورده)، برچسب، اتصال به یک یا چند اینباند (Multi-Sub)، ترتیب نمایش، آمار فروش |
| **کد تخفیف** | درصدی + مبلغ ثابت، حداکثر استفاده، تاریخ انقضا |
| **پرداخت USDT (TRC20)** | آدرس ولت، نرخ تتر، تبدیل خودکار مبلغ، تأیید خودکار TXID از بلاکچین (Tronscan/TronGrid)، بررسی دوره‌ای پرداخت‌های در انتظار |
| **کارت به کارت** | شماره کارت/صاحب/بانک، ارسال شماره پیگیری + تصویر رسید (تا ۳MB)، صف بررسی و تأیید/رد با یادداشت |
| **زرین‌پال** | Merchant رمزنگاری‌شده، Sandbox، Callback خودکار و تحویل فوری |
| **تحویل خودکار** | ساخت کلاینت روی اینباندهای پلن، صفحه سفارش عمومی `/shop/o/<token>` با QR و لینک ساب، تمدید با `?renew=<subToken>`، ارسال لینک به تلگرام مشتری |
| **کیف پول نماینده‌ها** | قیمت هر GB / هر روز (پیش‌فرض + اختصاصی هر نماینده)، کسر خودکار هنگام ساخت/تمدید کلاینت، سقف بدهی، شارژ با USDT/کارت/زرین‌پال، شارژ/کسر دستی توسط مالک، دفتر تراکنش‌ها |
| **مینی‌اپ تلگرام** | دستور `/shop` و `/wallet` در بات، دیپ‌لینک `t.me/<bot>?start=store_<slug>`، تأیید هویت مشتری با `initData` |
| **وب‌هوک و اعلان** | رویدادهای `order.created / order.paid / order.fulfilled / order.canceled / payment.review / payment.rejected / wallet.topup` + اعلان تلگرام برای رسیدهای جدید |

### راه‌اندازی فروشگاه (۳ دقیقه)

1. **پنل → فروشگاه → تنظیمات**: فروشگاه را فعال کنید، slug و عنوان بدهید و حداقل یک روش پرداخت (USDT / کارت / زرین‌پال) را فعال کنید.
2. **فروشگاه → پلن‌ها**: پلن بسازید و اینباند(های) هدف را انتخاب کنید.
3. لینک فروشگاه را از تب «نمای کلی» کپی کنید یا در بات تلگرام `/shop` بزنید.
4. **سفارش‌ها**: رسیدهای کارت‌به‌کارت را در تب «پرداخت‌ها» تأیید/رد کنید. USDT و زرین‌پال خودکار تحویل می‌شوند.
5. **(مالک) کیف پول → نماینده‌ها و قیمت‌گذاری**: قیمت هر GB/روز را تنظیم و «کسر هزینه» را فعال کنید تا هر نماینده از موجودی خود هزینه کند.

### ارتقا از مرحله ۲-الف

```bash
cd srpanel
git pull   # یا کپی فایل‌های جدید
# متغیرهای جدید (اختیاری) در .env:
#   SRP_UPLOAD_DIR=/app/uploads      # محل رسیدها (ولوم srp_uploads)
#   SRP_TRONGRID_KEY=                # کلید TronGrid برای تأیید سریع‌تر USDT (اختیاری)
docker compose up -d --build         # entrypoint خودکار prisma db push را اجرا می‌کند
```

- آدرس Callback زرین‌پال: `https://<domain>/api/shop/zarinpal/callback` (خودکار ست می‌شود؛ فقط دامنه را در پنل زرین‌پال تأیید کنید).
- برای دامنه اختصاصی فروشگاه، در «تنظیمات → برندینگ» دامنه را ثبت و رکورد `CNAME`/`A` را به سرور بدهید؛ Caddy گواهی را خودکار می‌گیرد.

## 🚀 نصب سریع (Docker)

پیش‌نیاز: یک سرور Ubuntu 22.04+ با دامنه‌ای که به IP سرور اشاره می‌کند.

```bash
git clone https://github.com/SRNetWork-ai/SR-Panel.git srpanel
cd srpanel
bash install.sh
```

اسکریپت `install.sh`:
1. Docker و Docker Compose را (اگر نباشد) نصب می‌کند
2. دامنه، نام کاربری و رمز مالک را می‌پرسد و فایل `.env` را با کلیدهای امن تصادفی می‌سازد
3. سرویس‌های `db` (PostgreSQL)، `web`، `worker` و `caddy` (HTTPS خودکار) را بالا می‌آورد

بعد از چند دقیقه: `https://YOUR-DOMAIN` → ورود با نام کاربری/رمز مالک.

### نصب دستی

```bash
cp .env.example .env        # مقادیر SRP_DOMAIN, SRP_SECRET, SRP_OWNER_PASSWORD, POSTGRES_PASSWORD را تغییر دهید
docker compose up -d --build
docker compose logs -f web
```

### توسعه محلی

```bash
npm install
cp .env.example .env         # DATABASE_URL را به یک PostgreSQL محلی بدهید
npm run db:generate && npm run db:push
npm run dev                  # http://localhost:3000
npm run dev:worker           # در ترمینال دوم
```

## 🧩 معماری

```
srpanel/
├─ apps/
│  ├─ web/        Next.js 16 (App Router) — UI + API routes + سابسکریپشن عمومی
│  └─ worker/     زمان‌بند (croner) — سینک سرورها، انقضا، پاک‌سازی
├─ packages/
│  ├─ core/       منطق دامنه: آداپتر 3x-ui، سرویس‌ها، لینک‌ساز (vless/vmess/trojan/ss)، امنیت
│  └─ db/         Prisma schema + client (PostgreSQL)
├─ docker/        Caddyfile, entrypoint
├─ docker-compose.yml, Dockerfile, install.sh
```

**مسیرهای مهم**

| مسیر | توضیح |
|---|---|
| `/login` | ورود (رمز + TOTP) |
| `/dashboard` `/clients` `/servers` `/admins` `/settings` `/audit` | پنل مدیریت |
| `/sub/<token>` | خروجی سابسکریپشن (base64) — `?format=links` برای متن خام |
| `/s/<token>` | صفحه وب کلاینت (برندشده، QR، افزودن به برنامه) |
| `/api/*` | REST API داخلی (سشن کوکی) |

## ⚙️ متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `SRP_DOMAIN` | — | دامنه پنل (Caddy گواهی HTTPS می‌گیرد) |

| `SRP_SECRET` | — | کلید رمزنگاری (حداقل ۳۲ کاراکتر تصادفی) |

| `SRP_SYNC_INTERVAL_SEC` | `60` | فاصله سینک سرورها |

## 🔔 راه‌اندازی تلگرام و بکاپ

1. در [@BotFather](https://t.me/BotFather) یک بات بسازید و توکن را کپی کنید.
2. پنل → **یکپارچه‌سازی** → تب **تلگرام** → توکن را وارد و ذخیره کنید.
3. به بات `/id` بفرستید (یا آن را به گروه مدیریت اضافه کنید و همان‌جا `/id` بزنید) و شناسه را در **Chat ID مدیریت** قرار دهید → **تست اتصال**.
4. برای هر ادمین، در صفحه **ادمین‌ها** فیلد «آی‌دی تلگرام» را پر کنید تا به بات دسترسی داشته باشد و اعلان کلاینت‌های خودش را بگیرد.
5. پنل → **بکاپ‌ها** → ساعت اجرا و تعداد نگه‌داری را تنظیم کنید. فایل‌ها در ولوم `srp_backups` ذخیره و (در صورت فعال بودن) به تلگرام ارسال می‌شوند.

بازگردانی بکاپ:

```bash
docker compose stop web worker
gunzip -c srpanel-YYYY-MM-DD.sql.gz | docker compose exec -T db psql -U srpanel -d srpanel
docker compose start web worker
```

نمونه استفاده از API:

```bash
curl -H "Authorization: Bearer srp_xxx" https://panel.example.com/api/v1/clients?take=20
```

## 🔐 نکات امنیتی

- رمز پنل‌های 3x-ui فقط به صورت رمزنگاری‌شده (AES-256-GCM با کلید مشتق از `SRP_SECRET`) ذخیره می‌شود.
- اگر `SRP_SECRET` را تغییر دهید، رمز سرورها باید دوباره وارد شود.
- برای مالک حتماً 2FA را از مسیر تنظیمات فعال کنید.
- این مخزن را **Private** نگه دارید.
